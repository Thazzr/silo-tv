# Tools

Dieser Ordner enthält laufende Entwicklerwerkzeuge für lokale Verifikation und Wartung (PowerShell 7, `pwsh`).

| Skript                | Zweck                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `verify.ps1`          | Das vollständige Gate, ein Strang nacheinander: Skripttests, `typecheck`, `lint`, `unit tests`, `build`, `bundle check`, `e2e`, `package`. Ein fehlgeschlagener Schritt stoppt nichts, nur wenn `build` scheitert, werden `bundle check`, `e2e` und `package` übersprungen. Am Ende steht eine Tabelle mit Dauer und Ergebnis. `-Only "<Schritt>",…` führt nur einzelne Schritte aus (unbekannter Name: Exit-Code 2). Auch als `npm run verify`. |
| `verify.Tests.ps1`    | Testet die Pass/Fail-Logik von `verify.ps1` (ohne Pester, mit einem gefälschten npm) und läuft als erster Schritt des Gates. Die Env-Marke `VERIFY_SCRIPT_TESTS_RUNNING` verhindert, dass der Schritt sich selbst erneut startet.                                                                                                                                                                                       |
| `update-changelog.ps1` | Regeneriert `CHANGELOG.md` mit [git-cliff](https://git-cliff.org) aus der Conventional-Commits-Historie. `-WithCommit` nimmt einen noch nicht committeten Commit-Subject mit auf, `-Tag` und `-TagMessage` setzen vorher einen Versions-Tag. `CHANGELOG.md` wird nie von Hand editiert.                                                                                                                                  |
